## 项目概述

Chrome Extension **Manifest V3**，在京东/天猫商品详情页与淘宝搜索列表页注入 content scripts，解析 DOM，输出与 **product-validator** 中 `ProductSource` / `StandardProduct` 规则对齐的 JSON 对象，以 **JSONL**（NDJSON）形式缓存或下载。

设计要点：

- **无构建步骤**：源码即扩展，直接「加载已解压的扩展程序」。
- **人类行为模拟**：`human-scroll.js`（贝塞尔滚屏）、`human-mouse.js`（轨迹点击）降低懒加载漏字段。
- **双通道 UI**：`popup/` 与页面浮动面板均可触发同一套提取逻辑。
- **手动提取**：不提供自动翻页抓取；详情缓存上限 10000 条，超出自动删除最旧。
- **导出**：提取默认只写入缓存，不自动下载；「统一下载全部 JSONL」把缓存导出为单个 JSONL 文件，供 everymarket 后台（`/dashboard/cn_product_imports`）手动导入。

### 页面类型与脚本加载

| URL 模式 | 平台判定 | 自动注入（manifest content_scripts） |
|----------|----------|-------------------------------------|
| `detail.tmall.com/item.htm*` | taobao | jd-page-url, tmall-extractor, download, tmall-content |
| `item.jd.com/*.html*` 等 | jd | jd-page-url, jd-scroll-pause, human-scroll, extractor, download, content |
| `s.taobao.com/search*` | taobao（list） | jd-page-url, taobao-risk, jd-scroll-pause, human-scroll, human-mouse, taobao-search-extractor, download, taobao-search-content |

`popup.js` 在 `sendMessage` 失败时会按平台调用 `chrome.scripting.executeScript` 补注入（`injectItemScripts(tabId, platform)` / `injectSearchScripts(tabId)`）。

## 核心模块

### extractor.js（京东详情页）

- `extractJdProduct(options)` → ProductSource 形状 payload（含 `_validation_errors`）。
- 数据源：DOM（新老两套京东页面结构）+ `pageConfig` + `club.jd.com` 评价摘要 API。
- 图文详情：`hasPageDescriptionLoaded()` 要求 DOM 中存在 ≥20 字符的详情区，否则弹「请先滚动加载图文详情」。

### tmall-extractor.js（天猫详情页）

- `extractTmallProduct()` → ProductSource 形状 payload。
- 目标结构：tbpc SSR 布局。所有选择器用 `[class*="xx--"]` 前缀匹配（类名带哈希后缀）。
- 关键字段：
  - 标题 `.mainTitle--*`；价格 `[class*="highlightPrice--"]`
  - 图集 `#mainPicImageEl` + `#picGalleryEle img`
  - SKU 变体 `#skuOptionsArea .skuItem--*`（label + `valueItem--*` 值列表，笛卡尔积生成 variants）
  - 参数 `.paramsWrap--*`（emphasis + general 两类行）
  - 图文详情 `#imageTextInfo-content`（净化：去 `descV8-charity`/`<a>`/data 占位/多余属性）
  - 图片取 `src` → `data-savepage-currentsrc` → `data-savepage-src`（兼容保存为 data: URL 的网页）

### taobao-search-extractor.js（淘宝搜索列表）

- `extractTaobaoSearchProducts(options)` / `extractTaobaoSearchProductsMultiPage(options)` → 列表级 ProductSource。
- 卡片与链接/价格/销量/店铺识别见 `findSearchCards` / `parseSearchCard`。

## 消息协议

### Content scripts → 页面（tabs.sendMessage）

| 消息 | 发送方 | 接收方 | 响应 |
|------|--------|--------|------|
| `EXTRACT_JD_PRODUCT_WITH_SCROLL` | popup | content.js | `{ ok, data, saved, validation_errors }` |
| `EXTRACT_TMALL_PRODUCT` | popup | tmall-content.js | 同上 |
| `EXTRACT_TAOBAO_SEARCH_LIST` | popup | taobao-search-content.js | `{ ok, data }`（data.products） |

### Content scripts / popup → background（runtime.sendMessage）

| 消息 | 说明 | 响应 |
|------|------|------|
| `APPEND_JSONL_RECORD` / `APPEND_AND_DOWNLOAD_JSONL` | 追加一条 product（去重 + 10000 条上限） | `{ ok, count, records, filename, maxRecords }` |
| `APPEND_JSONL_RECORDS` | 批量追加 products（淘宝列表整批写入，避免逐条读写 storage） | 同上 |
| `GET_JSONL_RECORDS` / `DOWNLOAD_JSONL` | 读取全部详情记录 | 同上 |
| `CLEAR_JSONL_RECORDS` | 清空详情缓存 | `{ ok }` |

## 本地存储

| key | 内容 | 说明 |
|-----|------|------|
| `cn_jsonl_records` | `ProductSource[]` | 详情缓存，最多 10000 条，超出删除最旧；导出 `cn-details-*.jsonl`（「统一下载全部 JSONL」） |

旧版 key（`jd_jsonl_records`、`jd_crawl_*`、`jd_product_url_queue`）在后台启动时自动迁移/清理。

## 数据模型 ProductSource

与 `em_product.ProductSource`（product-validator 仓库）对齐的字段集；下载的每行 JSON 可直接被 `StandardProduct` / `ProductSource` 校验：

```bash
python3 scripts/validate_sample.py scripts/tmall_product.json
```

关键约束（镜像自 em_product）：

- `description` 不能为空、不能含 `<a>` 标签
- `images` 以 `;` 分隔且每条以 `http` 开头
- `categories` 以 `>` 分隔且各段不重复
- `specifications` 每项只能有 `name` / `value`
- `variants[].sku` / `variants[].price` 必填

---

## 页面适配要点

- 天猫/淘宝类名带哈希后缀（如 `mainTitle--R75fTcZL`），一律用 `[class*="~--"]` 前缀匹配，避免硬编码完整类名；布局小改动一般不受影响。
- 保存网页（Save Page）会把图片本地化为 `data:` URL，真实地址在 `data-savepage-src` / `data-savepage-currentsrc` 属性；`imageSource()` 在处理两者。
- 京东图文详情懒加载，须先滚动；天猫 SSR 直接渲染，无需滚屏。

## 导出与导入（不包含定价/上传）

扩展不做价格计算与上传：提取默认只写入详情缓存，由「统一下载全部 JSONL」导出为单个 `cn-details-*.jsonl` 文件（每行一条 ProductSource）。定价与商品导入在 everymarket 后台完成（`/dashboard/cn_product_imports` 接受该 JSONL 文件）。

## 扩展与修改指南

接到「某字段没抓到」类问题时，按顺序排查：

1. 目标页面是否有该数据（F12 → Elements）。
2. `tryBuildProductFromDom` / `parseSpecificationsFromDom` 等相关解析函数选择器是否命中。
3. 保存整页 HTML 后用 `npm run test:tmall-saved -- <file>`（或 `test:saved`）离线回归。
4. 输出文件用 `python3 scripts/validate_sample.py <json>` 校验 StandardProduct。
